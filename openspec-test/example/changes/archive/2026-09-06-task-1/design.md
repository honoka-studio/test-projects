## Context

当前状态：

- 要创建的脚本不存在。

约束：

- `[proj]`指当前打开的项目的根目录。
- 脚本必须在 Windows Git Bash（MSYS2/MinGW/MSYS/Cygwin）下运行。
- 目标位置位于用户主目录（`~/.codex`、`~/.dsh`、`~/.claude`、`~/.agents/skills`、`~/.claude/skills`）。
- Windows 下创建真正的符号链接需要"开发者模式"或管理员权限，且 Git Bash 默认可能退化为复制。

## Goals / Non-Goals

**Goals:**

- 安装/卸载流程幂等，可重复执行且结果一致。
- 全局规则的删除仅针对"指向本项目文件"的链接，避免误删用户自有文件。
- 脚本与调用方的工作目录无关，始终以脚本自身位置解析项目根目录。

**Non-Goals:**

- 不处理跨平台（macOS/Linux 原生环境）以外的符号链接权限问题。
- 不校验技能目录内部结构（SKILL.md 等内容），只做目录级链接。
- 不提供交互式选择或增量卸载（一次卸载全部已安装条目）。

## Decisions

1. **使用 Bash + `set -euo pipefail`**
   - 选择：脚本采用 Bash 语法，并启用严格模式。
   - 理由：任务要求"Windows Git Bash 可运行"；严格模式让任何失败立即中止，避免半安装状态。
   - 备选：PowerShell 脚本——可行但与"Git Bash 脚本"的明确要求不符。

2. **以脚本位置解析项目根目录**
   - 选择：`PROJ_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"`。
   - 理由：`[proj]` 必须可靠地解析为项目根目录，与用户执行脚本时的 cwd 解耦。
   - 备选：使用相对路径——在不同 cwd 下不可靠，已排除。

3. **在 MSYS/MinGW 下强制原生符号链接**
   - 选择：检测 `uname -s` 为 `MINGW*/MSYS*/CYGWIN*` 时设置 `MSYS=winsymlinks:nativestrict`。
   - 理由：Git Bash 默认可能把 `ln -s` 变成文件复制；`nativestrict` 保证创建真正的符号链接，失败即报错。
   - 备选：`winsymlinks:native`——失败时静默回退为复制，会破坏"符号链接"这一契约，已排除。

4. **安装前先执行卸载**
   - 选择：`install.sh` 第一步调用 `./scripts/uninstall.sh`。
   - 理由：保证幂等——无论之前处于何种半安装/残留状态，安装都从干净状态开始，并复用同一套清理逻辑。
   - 备选：仅覆盖式重建——会遗漏 `installed.txt` 里记录但当前目录已不存在的残留技能链接。

5. **创建链接前删除同名条目**
   - 选择：以 `[ -e ] || [ -L ]` 判断（覆盖指向不存在目标的损坏链接），存在即 `rm -rf`，再 `ln -s`。
   - 理由：任务要求"若已存在同名文件/目录/符号链接则先删除"；`-L` 检查能覆盖损坏链接这一边界。
   - 备选：仅 `ln -sfn`——对已存在的目录不生效且行为随环境而异，已排除。

6. **卸载全局规则时校验目标，卸载技能时按名称删除**
   - 选择：`AGENTS.md`/`CLAUDE.md` 仅在"是指向本项目文件的符号链接"时删除（用 `readlink -f` 规范化后比较）；技能目录则按名称删除 `~/.agents/skills/<name>` 与 `~/.claude/skills/<name>` 下的同名目录或符号链接。
   - 理由：与任务流程描述一致——全局规则删除带目标校验，技能删除按名称。这是规格中明确的行为边界。
   - 备选：技能删除也做目标校验——更安全，但会偏离任务的明确要求，故不做。

7. **`installed.txt` 作为技能名清单**
   - 选择：每行一个技能目录名；安装时由当前 `skills/*/` 子目录生成，卸载时读取并与当前子目录名合并。
   - 理由：任务要求卸载时把 `installed.txt` 中的列表合并进来，以清理"历史上安装过、现已改名/删除"的残留链接。
   - 备选：卸载只扫当前目录——会漏掉已改名的残留链接，已排除。

8. **路径比较前统一规范化**
   - 选择：`canon()` 用 `readlink -f` 解析后把 `\` 统一替换为 `/`。
   - 理由：Windows 路径可能混用分隔符，直接字符串比较会误判，导致"指向本项目文件的链接"无法被识别。

## Risks / Trade-offs

- **Windows 原生符号链接需要权限** → 在脚本头部注释与 README 中说明"开发者模式或管理员权限"；通过 `nativestrict` 让失败显式报错而非静默降级。
- **技能按名称删除可能误删同名无关条目** → 这是任务明确要求的行为（技能删除按名称）；全局规则已做目标校验以降低风险。若后续需要，可改为目标校验，但这属于规格变更。
- **`installed.txt` 位于 `skills/` 下但会被 `skills/*/` 通配排除** → 通配仅匹配一级子目录且 `installed.txt` 是文件，不会把清单本身当技能处理。
- **`~/.claude/skills` 与 `~/.agents/skills` 目录可能不存在** → 安装时 `mkdir -p` 目标父目录；卸载时对不存在的条目直接跳过（`[ -d ] || [ -L ]` 判断）。
